limitcast limitcast.dev

Stretch your Claude Code plan

limitcast is a command-line tool that shows what fills your context, warns you before a usage window runs out, and stops new subagents that would use up the rest of it. Then it shows you what that saved. It reads data already on your machine. No logins. 

$ limitcast trim
Every Claude Code session starts at 102.7k tokens before your first message.

## Measured savings: ~6.2k tokens per session (6% of your starting context)
- Disable 9 MCP servers you haven't used in 14 days (~0.9k): postman, context7, ...
- Hide 66 skills from the model (~5.3k): dataviz, block-kit, ...

Where your plan goes

Claude Code and Codex plans meter usage in rolling windows, such as a 5-hour window and a weekly one. Two things use them up faster than most people notice.

Starting context

Every session loads about 100k tokens before you type: hook output, MCP server instructions and tool lists, skill listings, agent lists and CLAUDE.md files. That block is sent again on every turn and to every subagent.

Subagents

Each subagent starts with its own copy of that context. A few parallel subagents late in a window can use up the rest of it, and you find out when you're locked out.

What limitcast does

Each feature shows the exact text limitcast prints. The numbers are an example; yours come from your own readings and transcripts.

Runout forecast

Free limitcast status
  • For each limit window: percent used, burn rate, the clock time it runs out, and when it resets.
  • Claude Code passes its own limit readings to your status line; limitcast records them as they change. Codex is read from its session logs with no setup.
  • The burn rate is a straight-line fit over the last hour of the window. AT_RISK means you'll hit 100% before the reset; NEAR means 95% or more is used, even before there's a burn rate.
  • The weekly window is paced over the last full day, nights and idle time included, so one busy hour on Monday doesn't predict a runout by Wednesday. A burst that would use up the week within the next hour still triggers the warning and the guard.
  • Sessions of the same account share one history, so a short session still gets a forecast. Two accounts used in parallel never mix.
  • Daily allowance: for the weekly window, today's even share of what was left this morning, and how much of it today used: 7d 41% · today 6% left in the status line, a today column in status.
  • Which window first: when a window is on pace to run out, status ends with one line naming the one that runs out first and where else there is room. 
$ limitcast status
window     used  burn      runs out  resets     today     status
claude 5h  71%   +18.2%/h  16:40     17:00      -         AT_RISK
claude 7d  41%   +0.6%/h   -         Sun 03:00  6% left   OK
codex 5h   22%   +4.1%/h   -         18:12      -         OK

You'll hit Claude 5h first (16:40). Codex 5h has 78% left.

# in the status line:
5h 71% ⚠ out 16:40 · 7d 41% · today 6% left

Benefit: you see the lockout coming while there's still time to slow down, switch tools, or move heavy work past the reset.

Trim advisor

Free totals Pro names and cuts limitcast trim [--days N] [--share] [--apply]
  • Reads your latest session's transcript and counts the tokens each startup item actually loaded: SessionStart hook output, each MCP server's instructions and tool names, each skill, the agent list, and instruction files.
  • Compares that with what you used over the last N days (default 7): skill calls, slash commands and MCP tool calls.
  • Free shows your starting-context total and how much of it you haven't used.
  • Pro names each server, skill and hook to cut and what it costs.
  • --apply (Pro) makes the cuts through Claude Code's own settings: unused skills are hidden from the model (/name still works) and unused MCP servers are turned off for that project. Both files are backed up, and --undo reverses exactly what changed. Plugin skills, and servers whose exact name it can't confirm, are listed for /plugin and /mcp. If Claude Code later writes over those settings, the cuts are put back at the next session start; anything you turn back on yourself stays on.
  • --share prints totals with no project, file, skill, server or hook names, so it's safe to post.
  • --codex does the same for Codex: the AGENTS.md text it loads every session, and the MCP servers in ~/.codex/config.toml you haven't used. With Pro, --apply turns them off (enabled = false) and --undo restores the file exactly.
  • trim keep <name>[,<name>] (free) puts servers or skills on a keep-list that --apply never turns off or hides, in Claude Code, Codex and Grok, whatever the spelling (ego-browser and ego_browser match). trim shows what it would keep, trim keep --remove <name> drops one, and trim keep alone lists them. 
$ limitcast trim --apply
✓ Hid 66 skills from the model (`/name` still works): dataviz, block-kit, …
✓ Turned off 9 MCP servers for ~/work/api: postman, context7, …
Takes effect in your next Claude Code session. Undo: `limitcast trim --undo`

$ limitcast trim --codex --apply
✓ Turned off 3 Codex MCP servers (enabled = false in ~/.codex/config.toml): firecrawl, icm, node_repl

$ limitcast trim keep ego-browser
Kept by `trim --apply`: ego-browser

Benefit: every token you cut is saved on every turn of every session and every subagent. The numbers come from your own transcripts, not estimates.

Subagent guard

Free preview Pro blocks limitcast install --guard
  • A hook that runs before Claude Code starts a Task or Agent subagent, or Codex starts a spawn_agent.
  • Blocks the spawn only when that tool's own window is on pace to run out within 30 minutes and before it resets. The margin is set by LIMITCAST_GUARD_MINUTES.
  • While a Claude window is tight (NEAR or AT_RISK) but not about to run out, a new subagent that would run on your main model (or Opus) runs on Sonnet instead. An explicit Sonnet or Haiku is left alone.
  • Free installs run it as a preview: it never acts, and limitcast results shows what it would have stopped or switched, and whether those windows then ran out. When there's something to show, the status line says so once a week.
  • Built to stay out of your way: if it errors, it allows the call; a window already at 100% is left alone so paid extra usage keeps working; LIMITCAST_ALLOW=1 overrides it.
  • Daily hold (Pro, off by default): limitcast budget today on also holds new subagents once today's share of a weekly window is used up, until local midnight. With notifications on you get one message a day at 80% of today's share. A window already at 100% is left alone, LIMITCAST_ALLOW=1 overrides it, and free installs see what it would have held in limitcast results.
  • In Codex it is added after your existing hooks, so the ones you've already approved keep their approval. 
# a new subagent, 21 minutes before the window runs out:
limitcast: Claude 5h limit is 93% used and on pace to run out in ~21 min, before it resets. Finish with the agents already running, or set LIMITCAST_ALLOW=1 to spawn anyway.

# a new subagent while the window is tight:
limitcast: Claude 5h limit is 88% used; this subagent runs on Sonnet. Set LIMITCAST_ALLOW=1 to keep the main model.

# a new subagent once today's share is used up (budget today on):
limitcast: today's share of your Claude 7d limit is used up (6% of 5%). New subagents are held until midnight. Turn this off: `limitcast budget today off`, or set LIMITCAST_ALLOW=1 to spawn anyway.

Benefit: stops the most common way people lose the end of a window: a burst of subagents started when the window is nearly gone.

Subagent models by type

Pro limitcast subagent-model <type> <model>|off
  • New in 0.13. Pin a kind of subagent to a model and every new subagent of that kind runs on it: limitcast subagent-model Explore haiku. The model can be sonnet, opus, haiku or a full model id.
  • A spawn that names its own model keeps it. While a window is tight, a kind pinned to Opus is still moved to Sonnet. With no arguments the command lists what is pinned and the kinds you ran in the last 30 days.
  • Needs the guard (limitcast install --guard), which runs as a PreToolUse hook on the Task and Agent tools. results counts the subagents it moved; free installs record what it would have done.
  • limitcast cannot tell whether a cheaper model costs less of your limit per token, so check limitcast report --why after a week. 
$ limitcast subagent-model Explore haiku
Explore: haiku

Types you ran in the last 30 days: general-purpose (86), Explore (39), fork (39)

limitcast: Explore subagents run on haiku, the model you set for them.

Benefit: the subagents that only read and search stop running on your most expensive model.

Subagent receipts and budgets

Pro limitcast budget subagents <percent>|off
  • New in 0.11. When a subagent finishes, a SubagentStop hook prices it from its own transcript against your 5-hour window, using your own calibration, and shows you the receipt. The model never sees it.
  • limitcast budget subagents 15 makes the guard hold new subagents once subagents have used 15% of the current 5-hour window, until it resets. off removes it; limitcast budget subagents shows what's used so far.
  • New in 0.12. Before a new subagent starts, you see what that kind has cost you so far (the median and the largest, as a share of a 5-hour window). It appears once you have 3 priced runs, and only when a typical run is over 1% of a window or the window is near its limit. It is shown to you only and never blocks.
  • Pricing needs about a day of your own readings first; until then nothing counts against the budget. limitcast results totals your subagents and names the biggest. 
limitcast: that Explore subagent used ≈2.1% of your 5-hour window (34 calls, 180k new tokens).

$ limitcast budget subagents 15
Subagent budget: 15% of each 5-hour window. Used this window so far: ≈6.4%. Once it's spent, the guard holds new subagents until the window resets.

Benefit: you see which subagents are expensive while you're still working, and a cap keeps one busy hour of agents from eating the whole window.

Cold-cache warning

Free preview Pro limitcast install --guard
  • New in 0.11. After a long pause the prompt cache has expired, and your next message re-sends the whole context as new tokens, which count far more against your limit than cached ones.
  • When a session that re-sends 100k+ tokens has been idle longer than the cache lives (60 minutes; set LIMITCAST_CACHE_MINUTES), a UserPromptSubmit hook holds that first message once and says what it will cost. Send it again and it goes through, or run /compact first.
  • Never holds messages from background agents, /compact or /clear. If the hook fails, the message goes through. Free installs record what it would have held. 
limitcast: this session sat idle for 75 minutes, so its prompt cache has expired. Your message re-sends 300k tokens of context: ≈1.8% of your 5-hour window (≈0.03% if the cache were still warm). Send it again to go ahead, or run /compact first to shrink it.

Benefit: a "continue" after lunch no longer quietly costs a slice of your window; you decide whether to compact first.

Burn report

Pro limitcast report [--days N] [--out FILE]
  • Tokens by tool (Claude Code, Codex, Grok), day, project, model and session.
  • The share of tokens that went to subagents.
  • New in 0.13. The API-equivalent cost: what the same tokens would cost at the API's list prices (input, 5-minute and 1-hour cache writes, cache reads and output), as a total and per tool, day, project, model and session. It is a yardstick for how much your plan covers, not a bill. Claude models are priced; tokens on any other model are left out and counted separately, never as $0. Change a price or add a model in ~/.local/state/limitcast/prices.json.
  • Read from each tool's own local logs, including Grok's per-turn usage records. 
$ limitcast report --days 7
| tool   | tokens | output | cache reads | share | API-equivalent |
| claude | 863.6M |   2.9M |      840.8M |   99% |           $219 |
| codex  |  12.9M |  44.1k |       12.6M |    1% |              - |

API-equivalent cost: $219 at list prices for Claude models, not what a
subscription charges. 12.9M tokens on other models are not counted.
Subagents used 21% of Claude tokens.

Benefit: shows which projects, models or habits use up your plan, across all three tools in one report.

Plan advisor

Pro limitcast plan [--days N] · plan set <pro|max5|max20>
  • New in 0.13. Does your Claude plan fit how much you use? limitcast keeps the peak of every 5-hour and weekly window (for 120 days, starting when you install this version) and compares them with your plan.
  • It points to the next plan, with the monthly price difference, if you reached a limit three or more times (or the weekly limit once). It points to a smaller plan if that plan's limits would have held your busiest window and week with room to spare. It also shows what your Claude Code tokens would cost at API list prices, against your plan's price.
  • Tell it your plan first: limitcast plan set max20. It needs a week or two of history before it recommends anything. Prices (Pro $20, Max 5x $100, Max 20x $200) and the 5x and 20x multipliers are from claude.com/pricing on 26 October 2026; the Max 20x price was not on that page, and you can change any price in ~/.local/state/limitcast/prices.json.
  • Anthropic states the multiplier for the 5-hour session; the advisor assumes weekly limits scale the same way. It cannot see paid extra usage, which may cost less than a bigger plan if you rarely reach a limit. 
$ limitcast plan
Claude plan: Max 20x, $200 a month

Over 16 days: 63 five-hour windows with use (0 reached the limit, busiest
20%), 2 weekly windows (0 reached the limit, busiest 15%).
Max 5x would have fit: it has 1/4 of the usage per session, so your busiest
5-hour window (20%) would have been about 80% and your busiest week about
60%. That saves $100 a month ($100 vs $200).

At API list prices your Claude Code tokens of the last 16 days would have
cost $1,240 (about $2,325 a month at this pace), against $200 for your plan.

Benefit: a recommendation in dollars, from your own usage, instead of guessing which plan to pay for. (Example output; your numbers will differ.)

Where your tokens went

Pro limitcast report --why [--days N]
  • New in 0.12. Sorts the new tokens (input, cache writes and output; cached reads barely count against your limit) into subagents, session starts, cache rebuilds after an idle pause, tool results by tool and model output.
  • Splits subagents by type and model, shows all new tokens by model, lists the single steps that cost the most, and ends with what to ask for instead. Models may count differently against your limit, so the model tables show token counts, not window shares.
  • Claude Code only. Your transcripts are read once and cached, so later runs only read what changed. 
$ limitcast report --why
115.2M new tokens (input, cache writes and output; cached reads are left out).

| where                                                  | new tokens | share | 5-hour windows |
| Subagents                                              |      46.1M |   40% |           ≈3.1 |
| Model output (generated, then cached on the next call) |      18.3M |   16% |           ≈1.2 |
| Tool results                                           |      16.7M |   14% |           ≈1.1 |
| Cache rebuilds after an idle pause                     |      15.5M |   13% |           ≈1.0 |
| Session starts, headless runs (563)                    |      14.8M |   13% |           ≈1.0 |
| Session starts, interactive (47)                       |       4.0M |    3% |           ≈0.3 |

Heaviest scheduled-job starts

Pro limitcast report --jobs [--days N]
  • New in 0.12. A script or scheduled job that calls claude -p starts a fresh session every run and pays your whole starting context again. limitcast groups those headless runs by the first 45 characters of their prompt and shows runs, new tokens at start, starting prompt size, cold starts and calls per run.
  • A start is cold when more than half of its prompt was new tokens, not served from the prompt cache. The report shows how the gap since the job's last run decides that, and what the cold runs cost beyond the same job's warm ones.
  • It ends with how to launch a job leaner. Prompt text is shown on your machine only: don't paste the report publicly unredacted. 
$ limitcast report --jobs
566 headless runs spent 14.8M new tokens just starting: 13% of all new tokens.

| job (first words of its prompt)        | runs | new at start | prompt | cold |
| Prepare the nightly brief for the team |  283 |        25.6k |  34.4k |  99% |
| Update the weekly status canvas        |  154 |        32.4k |  32.4k | 100% |
| Review this change for security issues |  106 |        15.3k |  17.5k |  79% |

Benefit: finds the scheduled job that quietly spends a slice of your plan on every start. (Example job names changed.)

Starting-context alerts

Pro limitcast install --alerts
  • At the start of each session, tells you when your starting context grew by about 1k tokens or more, and names what grew.
  • The message is shown to you only, never to the model. It runs in about 0.3 seconds.
  • Once a week, one line on what limitcast did: limits reached, how far ahead it warned, subagents stopped, tokens not re-sent. 
limitcast: your Claude Code starting context grew ~3.4k tokens since your last session (MCP server instructions: linear new~2.1k, Instruction files: ~/CLAUDE.md +~1.3k). Run `limitcast trim` for details.

limitcast this week: 2 limits reached, warned ahead on 2 (avg 38 min), guard blocked 3 subagents, moved 5 to Sonnet, 1.9M tokens not re-sent. Details: limitcast results

Benefit: catches a new plugin, a growing CLAUDE.md or a chatty hook the day it appears, not weeks later.

Large tool-output notice

Pro limitcast install --alerts
  • New in 0.12. A PostToolUse hook estimates each Bash, Read, Grep, WebFetch and MCP tool result from its size. At about 20k tokens or more it tells you, once per tool per session, with what to ask for next time. LIMITCAST_TOOL_TOKENS changes the threshold.
  • Shown to you only, never to the model, and it adds about 30 ms per call. If the hook fails, the call goes through. To add it to an existing install, run limitcast install --alerts again. 
limitcast: that linear list_issues result was ≈25k tokens (≈0.17% of a 5-hour window to write, then re-read on every later call). Next time: ask for fewer fields and a smaller limit.

Benefit: one oversized result is easy to miss; this names it the moment it happens, and what to ask for instead.

Results

Free limitcast results [--days N] [--share]
  • Opens with what happened since limitcast started watching: tokens not re-sent (your smaller starting context times every model call, read from your transcripts), how many of the limits it watched you approach it warned you about and how far ahead, and the subagents the guard stopped.
  • Then the last week in detail: every limit you hit, with the forecast replayed from only the readings it had at the time, and what happened to each window after the guard acted.
  • The totals outlast the 8 days of raw readings: a daily background update keeps them current. --share prints totals only, safe to post.
  • Shows what a smaller starting context was worth against your 5-hour limit, calibrated from your own readings: how many new tokens, and how many cached ones, move your meter by 1%. Cached tokens count far less, which is why long sessions and subagents, not your CLAUDE.md, are what run you out.

Benefit: you can check that limitcast works, and see what it's worth, from your own data.

Acts for you

Pro notify · budget · after-reset · results --html
  • limitcast notify on sends one desktop notification when a Claude window turns NEAR, AT_RISK or HIT, and when it resets after a HIT. On macOS they come from a tiny limitcast notifier app (no Dock icon), so "limitcast" has its own entry in System Settings → Notifications; allow it there, and pick Persistent to keep a warning on screen until you dismiss it.
  • New in 0.11: limitcast notify ntfy <topic> also sends every notification to your phone through ntfy (install the ntfy app and subscribe to the topic), and limitcast notify webhook <url> to a Slack or Discord incoming webhook. off removes either. They're sent in the background, so no hook waits on the network.
  • New in 0.11: every day limitcast re-measures how many tokens move your 5-hour meter by 1%. When that shifts by 15% or more against the weeks before, you get a notification that your limit itself changed.
  • limitcast after-reset -- <command> waits for the window to reset, then runs the command (add --detach to run it in the background).
  • When the current Claude account is near its limit, the status line points to your other account with the most room, and status lists every account limitcast has current readings for.
  • Past ~150k tokens re-sent per model call, the status line suggests /compact. If you use your own status line, it stays as it was and the limitcast line (with this suggestion) goes on the line under it.
  • limitcast results --html puts results, your current windows and the burn report on one page. 
# desktop notification (and your phone or Slack, if you set one):
limitcast — Claude 5h limit is on pace to run out at 16:40, before it resets at 17:00.
limitcast — Your Claude limit looks smaller: 1% of the 5-hour window now takes ~139k new tokens, down from ~167k.

# status line, when you need it:
limitcast: ⇄ other account 5h 12% · 7d 30% · ctx 162k · /compact

$ limitcast after-reset --detach -- claude -p "run the full test suite"
Will run at 17:00 (after the claude 5h reset), in the background.

Benefit: you hear about a limit before you hit it, and the heavy work waits for the reset instead of you.

Grok

Free Pro install · budget grok <usd> · trim --grok
  • New in 0.12. limitcast install wraps Grok's status line (the session model, context % and cost on one line, with the limitcast forecast under it). --guard adds a guard for spawn_subagent.
  • limitcast trim --grok measures Grok's system prompt and tool definitions and the MCP servers in ~/.grok/config.toml you haven't used. Free shows totals; Pro names them and turns them off (--undo restores the file).
  • Grok stores what you spent, not a percentage, so the status line shows grok 5h $X · 7d $Y until you set a dollar cap with limitcast budget grok 20 (Pro). Then status forecasts that window and the guard blocks new Grok subagents when it is on pace to run out.

Benefit: the same forecast, guard and trim for Grok, once you tell limitcast what a 5-hour window is worth to you.

Setup and upkeep

Free install · uninstall · doctor [--fix] · trial
  • install backs up ~/.claude/settings.json and keeps your status line looking exactly the same while it records readings. Running it twice is safe. It then shows your starting context right away.
  • uninstall restores your original settings exactly.
  • doctor checks setup, data freshness and the license, and tells you plainly if Claude Code, Codex or Grok changed the log format limitcast reads. It also runs once a day in the background: a problem shows ⚠ run limitcast doctor in the status line.
  • Hooks go through a small launcher that survives Node upgrades: if the Node it used is gone, it finds limitcast on your PATH, and if that's gone too, your status line still shows and every hook allows. doctor --fix re-installs with the current Node.
  • Already installed with --guard before 0.11? Run limitcast doctor --fix to add the subagent receipts and the cold-cache warning.
  • limitcast trial turns on Pro for 7 days on this computer, with no card, once.
  • The Claude Code plugin adds /limitcast:status, /limitcast:results and /limitcast:trim inside a session.

Privacy

  • Your usage data stays on your machine. Everything is read from files that already exist there.
  • The free version makes no network calls.
  • A Pro license talks to Polar, the payment and licensing service, only to activate, for a weekly background check, and to deactivate. Each call sends the license key and your computer's name.
  • Phone and webhook notifications (Pro) are off until you turn them on. Then each notification's text goes to the service you chose, ntfy.sh or your webhook, and nothing else does.
  • Hooks never wait on the network.

Get started

npm install -g limitcast     # or: brew trust samstull9007/limitcast && brew install samstull9007/limitcast/limitcast
limitcast install            # free: status-line recorder
limitcast trial              # Pro free for 7 days, no card
limitcast activate <key>     # Pro
limitcast install --guard    # the subagent guard (free: preview only)
limitcast doctor
limitcast results            # what limitcast did for you

Requires Node 20 or later on macOS or Linux. Homebrew 7 and later asks you to trust a third-party tap before installing from it, hence the brew trust. Restart Claude Code after installing.
