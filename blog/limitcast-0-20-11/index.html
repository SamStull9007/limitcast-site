Limitcast 0.20.11: fixes a Windows failure when commands overlap

Sam Stull · 27 November 2026

Limitcast 0.20.11 is available on npm. It fixes a Windows failure where two Limitcast commands running at the same time could exit with an error and lose a settings change. macOS and Linux are unchanged.

All features remain free under the MIT License. Limitcast runs locally on macOS, Linux and Windows with Node.js 22 or later. The Claude Code, Codex and Grok plugins have also been updated to 0.20.11.

What went wrong on Windows

Limitcast saves its settings and state by writing a temporary file and then renaming it over the real one, so a hook that reads at the same moment never sees a half-written file. On Windows, that rename is refused with EPERM while another process has the destination file open. When two Limitcast commands overlapped, one of them could hit that refusal, exit with status 1 and drop its change.

How it was found

Limitcast's own tests include one that runs limitcast trim keep from eight processes at once. On the Windows runner it failed now and then. The test threw away the command's error output, so the failure only said that the command exited with 1.

With the error output kept, 22 of 960 runs of that test on Windows (2.3%) failed, and every failure was the same EPERM: operation not permitted, rename on the settings file.

The fix

On Windows, Limitcast now retries that rename for up to two seconds when it is refused with EPERM, EACCES or EBUSY, which is how the other process lets go of the file. Any other error, and every error on macOS and Linux, is still raised at once. Three unit tests cover the retry, its time limit and the errors that are not retried.

With the fix, the same 960 runs on Windows had no failures.

How the release was checked

The 0.20.11 release commit passed 348 tests and all 11 CI jobs: lint, security and the test suite on Ubuntu, macOS and Windows with Node.js 22, 24 and 26. The publication preflight confirmed that before the package was published. The tarball downloaded from npm has the same checksum as the tested package, and the GitHub release and the Homebrew formula use that file.

One limit on the evidence: the 960-run comparison used Windows with Node.js 24. Node.js 22 and 26 on Windows ran once each in the CI matrix.

Upgrade

npm install -g limitcast@0.20.11
# or
brew upgrade limitcast

Then run limitcast doctor, and restart Claude Code, Codex and Grok. The full list of changes is in the 0.20.11 release notes.
