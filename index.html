How it works

Trim advisor (Pro)

Measures what your latest session loaded before you typed: hook output, MCP servers, tool names, skills, agents, instruction files. Then names the ones you haven't used, with the tokens each one costs you.

Subagent guard (Pro)

Blocks a new subagent in Claude Code or Codex when that window is on pace to run out before it resets. Never blocks once you're past 100%, so extra usage keeps working.

Burn report (Pro)

Claude Code, Codex and Grok tokens by day, project, model and session, plus the share your subagents use.

Runout forecast (free)

Burn rate and the clock time each 5-hour and weekly window runs out, for Claude Code and Codex. The weekly window is paced over the last full day, nights included, so one busy hour doesn't cry wolf; a warning at 95% even before there's a rate.

FAQ

Does it send my code or prompts anywhere?

No. limitcast reads the limit readings Claude Code passes to your status line and the logs Claude Code and Codex already keep on your disk, and none of that leaves your machine. The only network calls are for a Pro license key: once to activate, a weekly re-check, and when you deactivate. They send your license key and computer name to Polar, our payment provider. The status line and hooks never wait on the network, and Pro keeps working offline for 30 days after the last check.

Does it use my Claude login?

No. It never touches your subscription credentials, so it can't put your account at risk.

I use extra usage past my limit. Will the guard block me?

No. Once a window is used up, limitcast steps aside and leaves it to Claude Code. The guard only acts while you're heading toward a limit.

Does it work with Codex and Grok?

Codex: yes, forecasts, the subagent guard and the burn report, from the logs Codex already writes. Grok: the burn report covers your Grok tokens, but Grok keeps no limit readings on disk, so there's no Grok runout forecast and the guard never blocks Grok.

What if I have two Claude accounts?

Sessions of the same account share one history (matched by their limit reset times and usage that only rises), so even a short session gets a forecast, and two accounts used in parallel never mix.

Will one heavy hour make it say I'll run out of my weekly limit?

No. The 5-hour window is forecast from the last hour's pace. The weekly window uses your average pace over the last full day, idle time included, so a burst on Monday doesn't predict a runout by Wednesday. The exception is a burst that would use up the week within the next hour: that still triggers the warning and the subagent guard.
