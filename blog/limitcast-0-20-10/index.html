Limitcast 0.20.10 fixes subagent caps under parallel starts

Sam Stull · 25 November 2026

Limitcast 0.20.10 is available on npm. The patch makes the per-session subagent cap hold when several starts arrive together. It also makes the scheduled-jobs report and Codex diagnostics more precise.

Subagent caps count starts, even in parallel

In 0.20.9, parallel hook processes could read the same count and each allow an agent to start. Limitcast now checks the count and reserves a slot together. It counts starts the guard admits, including any the host later rejects. Completion receipts still report usage, and a delayed receipt or long-running agent no longer reopens a slot.

With the guard installed, set a cap for one type in Claude Code, Codex, or Grok. Type names are case-insensitive. Resuming an existing subagent skips the count. 

limitcast budget type Explore 1
limitcast budget type explore off

What the jobs report can tell you

limitcast report --jobs now labels connector activity as main-thread evidence. A connector with no recorded main-thread call can still be used by a child agent or a hook. Check those dependencies before testing a run with hooks disabled.

The report also describes how much of the prompt was served from cache. It leaves the cause of a cache miss open.

Codex doctor shows which hooks are disabled

limitcast doctor reports disabled Codex hooks separately from hooks that need approval. A trusted hook can still be disabled, so the distinction tells you what to check in /hooks.

Install the patch

npm install -g limitcast@0.20.10
limitcast doctor

All 11 CI jobs passed on the release commit. In a fresh npm install, a cap of one admitted exactly one of six parallel test requests. The full list of changes is in the 0.20.10 changelog.

limitcast forecasts when each Claude Code, Codex and Grok window runs out, and holds runaway subagents before they burn the rest of it. It is free and MIT licensed.
